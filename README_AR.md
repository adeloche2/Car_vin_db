# GVIDB — قاعدة البيانات العالمية لتعريف المركبات

GVIDB مشروع مفتوح لتجميع بيانات الشركات والموديلات وقواعد ترميز أرقام هياكل المركبات VIN، بهدف بناء محرك بحث وفك محلي يعمل دون اتصال بعد تنزيل البيانات وقواعد الترميز.

## الهدف النهائي

عند إدخال رقم VIN، يسعى النظام إلى تحديد:
- الشركة المصنّعة وبلد/جهة التسجيل وفق WMI.
- فئة المركبة: سيارة، دراجة نارية، دراجة صغيرة، شاحنة، شاحنة خفيفة، حافلة أو غيرها.
- الطراز والسلسلة والفئة عندما تسمح قواعد الشركة بذلك.
- المحرك والهيكل ونوع الوقود وناقل الحركة إذا كانت الخانات أو وثائق الشركة تحددها.
- سنة الموديل ومصنع الإنتاج والرقم التسلسلي ضمن حدود المصدر.

لا يعتمد المشروع على تخمين اسم السيارة من أول ثلاثة أحرف. WMI يحدد هوية الشركة/المُصدر غالبًا، أما تحديد الطراز فيتطلب قواعد VDS خاصة بالشركة والسوق ونطاق سنوات الموديل.

## القرارات المعتمدة

1. النطاق العالمي (Global)، وليس السوق الأمريكي وحده.
2. أقصى مستوى تفاصيل متاح من وثائق الشركات والمصادر الرسمية.
3. الجمع من المصادر الرسمية والوثائق التقنية المتخصصة.
4. الاحتفاظ بالمصدر والرابط ومقتطف الدليل ونطاق التطبيق وحالة التحقق لكل قاعدة.
5. اللون VIN-only: لا يُستنتج لون الطلاء أو المقصورة من اسم الموديل أو السنة.
6. كتالوج الموديلات منفصل عن قواعد فك VIN.
7. لا تُستخدم القواعد غير المراجعة لإعطاء نتيجة مؤكدة.

## ما يحتويه المستودع

- تطبيق Flask بواجهة عربية RTL.
- قاعدة SQLite تنشأ محليًا.
- مستورد كتالوج VehiclesDB الإصدار 2026.11.3.
- تكامل NHTSA vPIC لفك VIN والبحث عن WMI.
- أدوات تطبيع VIN وفحص البنية وخانة التحقق الأمريكية وتقسيم الخانات.
- جامع سجلات الشركات ورموز WMI ووثائق Part 565/566.
- تنزيل وثائق VIN وحساب SHA-256 واستخراج نص PDF اختياريًا.
- مستورد JSON لقواعد الترميز التي تمت مراجعتها.
- اختبارات أولية ووثائق التشغيل ومخطط قاعدة البيانات ومصادر البحث.

## ما تم التحقق منه في كتالوج المركبات

أكد المستخدم من Termux استيراد 16,032 موديلًا:
- السيارات: 5,997
- الدراجات النارية: 6,196
- الدراجات الصغيرة: 1,459
- الشاحنات: 1,159
- الشاحنات الخفيفة: 795
- الحافلات: 426

كما أكد وجود 1,261 صفًا في جدول makes، و970 اسمًا وslug مميزًا، وعدم وجود تكرار في مجموعات (kind, make_slug, model_slug).

هذه النتائج من قاعدة المستخدم المحلية؛ ملف SQLite لا يُرفع إلى Git. ينشئ كل تثبيت قاعدة مستقلة ويستورد الكتالوج.

## التشغيل على Termux

```bash
pkg update
pkg install python git
git clone https://github.com/adeloche2/Car_vin_db.git
cd Car_vin_db
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python app.py
```

افتح http://127.0.0.1:8000 ثم استورد الكتالوج من تبويب «كتالوج الموديلات».

## جمع بيانات VIN/WMI

```bash
python -m gvidb.vin_research collect --with-wmi
python -m gvidb.vin_research download-docs --limit 100
python -m gvidb.vin_research stats
```

لتفعيل استخراج PDF:
```bash
pip install -r requirements-research.txt
```

## حالة المشروع وحدوده

المشروع يملك الآن تطبيقًا وكتالوجًا وجامعًا لمصادر VIN/WMI. لكنه **لم يجمع بعد كل أنماط VIN عالميًا ولم يستخرج كل جداول الطرازات من وثائق الشركات**. وثائق Part 565/566 التي يتم جمعها تحتاج إلى مراجعة واستخراج قواعدها قبل اعتمادها.

NHTSA مصدر رسمي غني لكنه يعكس أساسًا بيانات الشركات والمركبات المقدمة للسوق التنظيمية الأمريكية. لذلك لا نعتبره قاعدة عالمية كاملة. سيُضاف دعم مصادر إقليمية ووثائق شركات أخرى تدريجيًا مع توثيق النطاق والترخيص.
